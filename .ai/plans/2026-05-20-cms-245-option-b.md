# CMS-245 Option B Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add MDCMS built-in MDX components and first-class inline style props so AI/manual MDX can compose existing UI safely before visual composition UI ships.

**Architecture:** Built-ins are implemented once in a private internal React workspace package and injected into Studio and SDK rendering paths as normal catalog entries with `builtIn: true`. The shared MDX contract gains a first-class `style` prop type with shallow object validation. Current Studio insert surfaces hide built-ins while AI/manual MDX validation and rendering allow them.

**Tech Stack:** Bun workspaces, Nx TypeScript builds, React 19, TipTap Markdown/MDX pipeline, Zod 4 contracts, `@mdx-js/mdx` SDK renderer.

---

## Spec Delta

- `docs/specs/SPEC-007-editor-mdx-and-collaboration.md` now defines built-in MDX components, `builtIn: true`, reserved names, `MdcmsInlineStyle`, and `{ type: "style" }`.
- `docs/specs/SPEC-014-ai-assisted-studio-editing.md` now permits built-ins in AI-generated MDX and restricts style generation to flat inline style objects.
- `docs/specs/SPEC-006-studio-runtime-and-ui.md` now requires Studio to inject and preview built-ins without host registration.

- [ ] **Step 1: Add shared contract types**

Add `MdcmsInlineStyle = Record<string, string | number>`, add `builtIn?: true` to `MdxComponentCatalogEntry`, add `{ type: "style"; required: boolean }` to `MdxExtractedProp`, and update Zod/runtime validators to accept only flat objects with string/number values.

- [ ] **Step 2: Add contract tests**

- catalog entries accept `builtIn: true`
- `builtIn: false` is rejected or omitted according to the final schema choice
- `style` extracted props are accepted
- invalid style prop metadata is rejected
- valid inline style values pass runtime schema checks
- nested style objects/arrays/functions are rejected

- [ ] **Step 3: Map style to auto-form control**

Add a `style` auto-form control. Reuse the JSON object editor behavior for now, but keep the control name distinct enough for future visual style editing, e.g. `{ control: "style" }`.

- [ ] **Step 4: Extract conservative style props**

Recognize deterministic React inline style props, at minimum:

- prop name `style` typed as `React.CSSProperties`
- prop name `style` typed as `CSSProperties` imported from React

Normalize them to `{ type: "style", required }`. Do not normalize arbitrary object/record props as style unless the shape is clearly the MDCMS inline style alias introduced by this task.
